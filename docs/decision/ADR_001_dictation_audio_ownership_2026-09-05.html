Long-form dictation audio ownership

One recorder owns the microphone continuously from start through stop. The dictation application divides the received PCM stream into durable chunks without restarting that recorder, then transcribes and delivers those chunks in order. A bounded per-session encoder context may reduce inference work when it safely covers the complete padded chunk.

Decision summary

Long-form dictation uses one persistent parecord --raw child as the sole microphone owner. A reader inside the application owns every signed-16, 16 kHz, mono PCM byte until recorder EOF. It partitions those bytes exactly once into independent durable WAV files, records every chunk or visible gap under one ordered sequence, and lets transcription run behind capture without opening the microphone again. Stop drains the recorder, retains the final partial chunk, closes the session, and dispatches one paste after all live jobs reach an ordered terminal state. Inference may use a persisted encoder context that is validated to contain the maximum padded chunk. This mode is opt-in; legacy recorders and CPU, CUDA, and SYCL inference selection remain available unchanged.

Before

The long-session path tied each transcription slice to a separate recorder process. At a time boundary it stopped one process, finalized its WAV, and started another process against the same microphone. A delayed or failed reacquisition could create an empty file and a period for which no process owned incoming audio. Recovery could retain and retry existing files, but it could not reconstruct speech that never entered the application.

Why

Real three-minute dictation repeatedly delivered the beginning and final partial while omitting one or more middle chunks. The same microphone worked before and after each omission, so per-file retries did not close the ownership gap. A sealed 521-second production-path run later proved that one recorder plus application-owned partitioning can retain all 16,689,920 captured bytes across 65 chunks and one final paste.

Decisions

  1. One recorder process owns all live microphone bytes for a long-form session. Storage and inference boundaries are application events and never require microphone reacquisition.
  2. Every received PCM sample belongs to exactly one durable segment. The reader owns startup bytes, odd reads, EOF drain, and the final partial; no overlap or transcript matching may delete repeated speech.
  3. Every sequence advances as a durable job or a visible failure marker. Inference, storage, and recovery faults cannot silently block or omit later chunks.
  4. Recognition accuracy remains separate from capture integrity. Retained WAVs are the recovery source when the selected model substitutes or omits words. An optional encoder context is persisted and must cover the complete padded chunk.
  5. The path is opt-in and inference portability is unchanged. Legacy pw-record, parecord, and arecord behavior remains the default; CPU, CUDA, and SYCL selection stays independent.

Required acceptance evidence

  • A real production-path 1–150 recording uses one recorder PID, reconstructs every captured PCM byte from durable chunks, has no failed chunks, pastes once, and recognizes the exact sequence before any sealed holdout begins.
  • The first and only 1–500 holdout records capture and recognition independently. Capture fails if any PCM byte, durable chunk, ordering state, or final paste is missing; a recognition deviation is retained exactly and requires explicit human disposition.
  • Failure injection at an arbitrary second or later chunk proves WAV creation failure, partial manifest commit, cross-filesystem retention, and repeated ingest failure cannot deadlock ordering or suppress later recoverable chunks.
  • A recorder that writes more than the stderr pipe capacity and then writes more PCM must have all stdout PCM drained and its bounded diagnostic tail available.
  • Legacy mode and manifest-v1 tests preserve existing markers and configured RMS behavior; runtime-selection tests remain green for CPU, CUDA, and SYCL paths.
